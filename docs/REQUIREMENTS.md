# 요구사항 명세

이 문서는 기능·비기능 요구사항의 기준입니다. 기능별 상세 흐름과 예외 처리는 [FUNCTION_SPEC.md](FUNCTION_SPEC.md), 데이터 구조는 [DATABASE_ERD.md](DATABASE_ERD.md), 엔드포인트는 [API_SPEC.md](API_SPEC.md)를 봅니다.

우선순위: **M** = 필수(Must), 이 문서의 모든 M 항목은 반드시 구현합니다.

## 1. 기능 요구사항

### F1-01 회원 (인증)

| ID | 요구사항 | 우선순위 |
|----|----------|----------|
| FR-01-01 | 이메일, 비밀번호, 닉네임으로 회원가입할 수 있다. | M |
| FR-01-02 | 비밀번호는 단방향 해시(BCrypt)로 저장한다. | M |
| FR-01-03 | 이메일과 비밀번호로 로그인할 수 있다. | M |
| FR-01-04 | 로그인 성공 시 JWT 액세스 토큰을 발급한다. | M |
| FR-01-05 | 로그아웃 시 리프레시 토큰을 폐기하고 인증 쿠키를 제거한다. | M |
| FR-01-06 | 인증이 필요한 API와 화면은 유효한 JWT 없이 접근할 수 없다. | M |
| FR-01-07 | Google 계정으로 로그인할 수 있다 (OAuth 2.0 / OpenID Connect). | M |
| FR-01-08 | 같은 이메일로 가입된 계정이 있으면 Google 로그인 시 계정을 연결한다 (정책은 미결정 사항 참조). | M |

### F1-02 맛집 관리

| ID | 요구사항 | 우선순위 |
|----|----------|----------|
| FR-02-01 | 로그인한 회원은 맛집을 등록할 수 있다. | M |
| FR-02-02 | 맛집은 이름, 카테고리, 주소, 설명을 가진다. 전화번호와 좌표는 선택 항목이다. | M |
| FR-02-03 | 맛집 작성자 본인만 해당 맛집을 수정·삭제할 수 있다. | M |
| FR-02-04 | 맛집 목록은 페이지 단위로 조회한다. | M |
| FR-02-05 | 맛집은 카테고리 하나에 속한다. 카테고리 목록은 DB에서 관리한다. | M |
| FR-02-06 | 카테고리별로 맛집 목록을 필터링할 수 있다. | M |
| FR-02-07 | 맛집 이름과 주소에 대해 키워드 검색을 할 수 있다. | M |
| FR-02-08 | 맛집 상세 페이지에서 정보, 이미지, 평균 평점, 리뷰 목록을 볼 수 있다. | M |

### F1-03 맛집 이미지

| ID | 요구사항 | 우선순위 |
|----|----------|----------|
| FR-03-01 | 맛집 작성자는 이미지를 업로드할 수 있다. | M |
| FR-03-02 | 이미지는 AWS S3에 저장하고 DB에는 객체 키와 메타데이터만 저장한다. | M |
| FR-03-03 | 허용 형식은 JPEG, PNG, WEBP이며, 파일당 최대 5MB, 맛집당 최대 5장으로 제한한다. | M |
| FR-03-04 | 맛집 삭제 또는 이미지 삭제 시 S3 객체도 삭제한다. | M |
| FR-03-05 | 이미지가 없는 맛집은 기본 이미지를 표시한다. | M |

### F1-04 리뷰

| ID | 요구사항 | 우선순위 |
|----|----------|----------|
| FR-04-01 | 로그인한 회원은 맛집에 리뷰(내용 + 평점 1~5)를 작성할 수 있다. | M |
| FR-04-02 | 한 회원은 같은 맛집에 리뷰를 한 개만 작성할 수 있다. | M |
| FR-04-03 | 리뷰 작성자 본인만 리뷰를 삭제할 수 있다. | M |
| FR-04-04 | 맛집의 평균 평점과 리뷰 수를 계산해 표시한다. | M |
| FR-04-05 | 리뷰 작성·삭제 시 맛집의 평균 평점이 즉시 갱신된다. | M |

### F1-05 AI 리뷰 요약

| ID | 요구사항 | 우선순위 |
|----|----------|----------|
| FR-05-01 | 리뷰가 3개 이상인 맛집에 대해서만 AI 요약을 제공한다. | M |
| FR-05-02 | 요약은 OpenRouter를 통해 생성한다. | M |
| FR-05-03 | 생성된 요약은 DB에 캐싱하고, 다음 조회부터는 캐시를 사용한다. | M |
| FR-05-04 | 리뷰가 추가되거나 삭제되면 캐시를 무효화하고 다음 조회 시 재생성한다. | M |
| FR-05-05 | 리뷰가 3개 미만이면 요약 대신 안내 문구를 표시한다. | M |
| FR-05-06 | AI 호출이 실패해도 상세 페이지는 정상 표시되어야 한다 (요약 영역만 실패 안내). | M |

### F1-06 찜

| ID | 요구사항 | 우선순위 |
|----|----------|----------|
| FR-06-01 | 회원은 맛집을 찜할 수 있고, 찜을 취소할 수 있다. | M |
| FR-06-02 | 같은 맛집을 중복 찜할 수 없다. | M |
| FR-06-03 | 회원은 자신의 찜 목록을 페이지 단위로 조회할 수 있다. | M |

### F1-07 AI 맛집 추천

| ID | 요구사항 | 우선순위 |
|----|----------|----------|
| FR-07-01 | 회원이 입력한 취향 문장(예: "매운 국물 요리, 2명이서 조용한 곳")을 바탕으로 맛집을 추천한다. | M |
| FR-07-02 | 추천 후보는 DB에 등록된 맛집으로만 한정한다. | M |
| FR-07-03 | AI 응답에 포함된 맛집 ID가 DB에 없으면 결과에서 제외한다. | M |
| FR-07-04 | 추천 결과에는 맛집 ID, 이름, 추천 이유를 포함한다. | M |
| FR-07-05 | 후보 맛집이 없으면 AI를 호출하지 않고 안내 문구를 반환한다. | M |

### F1-08 메인 페이지

| ID | 요구사항 | 우선순위 |
|----|----------|----------|
| FR-08-01 | 메인 페이지에 카테고리 목록을 표시한다. | M |
| FR-08-02 | 메인 페이지에 최신 등록 맛집 목록을 표시한다 (기본 8개). | M |
| FR-08-03 | 카테고리를 클릭하면 해당 카테고리 목록 화면으로 이동한다. | M |
| FR-08-04 | 메인 페이지에서 맛집 검색 입력창을 제공한다. | M |

## 2. 비기능 요구사항

| ID | 구분 | 요구사항 |
|----|------|----------|
| NFR-01 | 보안 | 비밀번호는 BCrypt로 해시하고, 모든 보안 정보는 환경 변수로 주입한다. |
| NFR-02 | 보안 | 쓰기 API(등록, 수정, 삭제, 리뷰, 찜, 추천)는 인증과 권한 검사를 거친다. |
| NFR-03 | 보안 | 사용자 입력은 검증하고, Thymeleaf 기본 이스케이프를 유지한다. |
| NFR-04 | 보안 | 인증 쿠키는 HttpOnly, SameSite=Lax 속성을 설정하고, 운영 환경에서는 Secure를 설정한다. |
| NFR-05 | 성능 | 맛집 목록 조회는 페이지당 12개 기준으로 응답한다. 인덱스는 ERD 문서를 따른다. |
| NFR-06 | 성능 | AI 요약 캐시 덕분에 같은 맛집의 요약은 리뷰 변경 전까지 AI를 다시 호출하지 않는다. |
| NFR-07 | 안정성 | 외부 서비스(OpenRouter, S3, Google) 장애 시 사용자에게 안내 메시지를 보여 주고, 서버 오류 페이지로 떨어지지 않는다. |
| NFR-08 | 품질 | 기능 단위 테스트를 작성하고, CI(GitHub Actions)에서 테스트가 통과해야 배포한다. |
| NFR-09 | 호환성 | 최신 Chrome, Edge, Safari, 모바일 브라우저에서 레이아웃이 깨지지 않는다 (Bootstrap 5 반응형 그리드). |
| NFR-10 | 운영 | 로그에 비밀번호, 토큰, API 키를 기록하지 않는다. |
| NFR-11 | 설정 | 설정 값은 Spring 프로필(`local`, `prod`)로 분리한다. |

## 3. 제약 사항

- 기술 스택은 [PROJECT_OVERVIEW.md](PROJECT_OVERVIEW.md#5-기술-스택-고정)에 정의된 목록으로 고정합니다.
- 맛집 데이터는 사용자 등록으로만 생성합니다. 외부 데이터 자동 수집은 하지 않습니다.
- AI 기능은 OpenRouter 한 곳만 사용합니다.

## 4. 미결정 사항

구현 전에 결정이 필요한 항목입니다. 결정 전까지는 아래 "현재 가정"을 기준으로 문서를 작성했습니다.

| 번호 | 항목 | 현재 가정 | 결정 필요 이유 |
|------|------|-----------|----------------|
| Q1 | Google 로그인과 기존 이메일 계정 연결 | Google이 이메일 검증을 완료한 경우에만 같은 이메일의 기존 계정에 연결 | 계정 탈취 위험 |
| Q2 | 맛집 삭제 시 리뷰·찜·이미지 처리 | 맛집 삭제 시 리뷰, 찜, 이미지, AI 요약을 함께 삭제 (하드 삭제) | 데이터 복구 정책 |
| Q3 | 리프레시 토큰 보관 방식 | 리프레시 토큰은 DB 테이블에 해시로 저장하고 HttpOnly 쿠키로 전달 | 세션 만료와 로그아웃 처리 |
| Q4 | MySQL 위치 | 초기에는 EC2 내 MySQL 8 컨테이너 또는 패키지 설치 중 선택 | 운영 비용과 백업 방식 |
| Q5 | 맛집 수정 권한 | 작성자 본인만 수정·삭제 (관리자 권한은 이번 범위 외) | 운영 관리 필요 여부 |
| Q6 | AI 모델 | 환경 변수 `OPENROUTER_MODEL`로 지정 (코드에 고정하지 않음) | 모델 교체 용이성 |

Q1~Q6 중 하나라도 바뀌면 `FUNCTION_SPEC.md`, `DATABASE_ERD.md`, `API_SPEC.md`를 함께 갱신하고 `PROGRESS.md`에 기록합니다.
